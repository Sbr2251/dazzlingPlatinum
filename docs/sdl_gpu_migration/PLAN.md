## Why

The game targets PC and, later, phones (CLAUDE.md, "Target: the Mac app"). The simulator (`subprojects/libntr`)
renders with OpenGL 4.1, which iOS does not have and Android only has as GLES. The owner chose the **SDL3 GPU API**
(`SDL_gpu.h`): one renderer on Metal (macOS, iOS) and Vulkan (Windows, Linux, Android). A graphics overhaul
(lighting, shadows, widescreen) will be built on it afterwards, so the result must be clean to extend.

## Decisions (unchanged from v1 unless marked)

| Decision | Choice | Reason |
|---|---|---|
| Graphics API | SDL3 GPU API | Metal + Vulkan from one codebase |
| Platform library | Real SDL3 (not `sdl2-compat`) | SDL3 GPU headers cannot be mixed with SDL2 headers |
| SDL version (**changed**) | **3.4.16** everywhere | What Homebrew ships on the owner's Mac today; build the same tag from source on Linux so both platforms run one SDL |
| Shaders | GLSL 450, compiled offline to SPIR-V (`glslangValidator`), cross-compiled to MSL (`spirv-cross`), embedded | Existing shaders are GLSL; no HLSL/DXC; no runtime compiler on phones |
| OpenGL renderer | Kept behind `SIM_RENDERER=gl\|gpu` until the GPU renderer is proven equal | A/B against GL is the verification |
| `nx` / `prospero` targets | Not kept building | Not shipped |
| Where simulator changes live | `tools/macos/patches/libntr.patch` (and `libntrsystem.patch`), regenerated by the integrator | Project convention |
| Where the work runs (**changed**) | Devserver (Linux, Vulkan on lavapipe, GL on llvmpipe) for development; the owner's Mac (M4 Max, macOS 27) for Metal | 40 s full builds on the devserver; Metal exists only on the Mac |
| Renderer freeze (**new**) | No changes to the simulator's render files on `main` except through this migration, from the start of 1b until wave 3 signs off | Today's lanes rewrote the GPU 2D path and added capture, hi-res text and upscale sampling; a moving renderer forces every migration lane to rebase. Game-code work continues normally |

## How the renderer works today

All in `subprojects/libntr/libraries/sim/src` unless noted. `g3_handler.cpp` / `g3_draw.cpp` are not compiled.

- **3D.** Commands become `DrawCall`s (`sim_g3_CommandProcessor.cpp`, `sim_g3_GlobalState.cpp`);
  `sim_g3_GlRenderer.cpp` draws each immediately into an offscreen colour+depth framebuffer (256x192 x internal
  scale, default 4), per-draw cull, depth function `LESS` / `EQUAL`, depth write; translucent draws deferred to frame
  end. Textures: `sim_g3_Texture.cpp`, `sim_g3_TextureCache.cpp`. Shader pair `shaders/g3_*.glsl`, fog from
  `SIM_FogTable`.
- **2D.** At vblank `SIM_Render` (`sim_main.cpp`) runs `DrawEngine` per screen: CPU 2D (`sim_g2.cpp` -> RGBA layer
  textures -> `g2_fragment.glsl`) or GPU 2D (`sim_g2_gpu.cpp`: VRAM/OAM/palettes as integer textures, per-layer
  passes into layer textures, per-sprite scissored draws with depth). `g2_fragment.glsl` composites layers with
  blend/window registers, the OBJ-window mask and the `Upscale2DFilter` sampling. BG0 may be the 3D target.
- **Capture.** On frames with DISPCAPCNT enabled, the main engine is re-rendered into a 256x384 capture
  framebuffer, read back, blended with source B and written to emulated VRAM in RGB555.
- **Hi-res text overlay.** `sim_hirestext.cpp` draws mirrored dialogue glyphs at 4x over the composite.
- **Post pass.** Both screens composite into an offscreen frame; `shaders/post_*.glsl` draws it to the window with
  PostFX (`include/port/postfx.h`, docs/postfx.md), region mask, letterbox.
- **Overlay and present.** Dear ImGui (vendored) with SDL2 + OpenGL3 backends; swap.
- **Readback.** `glReadPixels` in `SIM_DebugFrame`, `sim_headless.cpp`, `sim_headless_control.cpp` (lockstep
  `screenshot`, centre probe) and the capture path.
- **SDL beyond the renderer.** Threads/mutexes/semaphores/timers/queues in `libraries/os` and
  `include/nitro/os/common/*.h`, audio (`sim_audio.cpp`), input/events (`sim_main.cpp`), libntrwifi (3 files), game
  `src/port/sim_icon.cpp`, `src/port/savedata_upgrade.c`.

SDL GPU differs: no global state; draws recorded in render passes on explicit targets; pipeline objects bake
cull/depth/blend; uniforms are pushed byte blocks; uploads in copy passes outside render passes; readback is a
download plus a wait; the swapchain may be BGRA. So 3D draws issued during the frame are recorded and replayed at
frame end, and every draw carries its full state.

## Verification method

1. **Lockstep A/B is the proof** (docs/headless_protocol.md, "Lockstep guarantee"). Same save, seed, RTC and command
   stream; the `screenshot` command; compare **decoded pixels** (SDL2 and SDL3 BMP headers differ; `run.py`'s reader
   uses the header's pixel offset already).
2. **`run.py` is the harness.** Add `--compare-backends` (workstream 1d'): run each scenario with `SIM_RENDERER=gl`
   and `=gpu` against the same references, like `--compare-renderers` does for 2D paths. Golden references stay per
   platform (`references/visual/` Linux, `references/visual_mac/` macOS).
3. **Gates per stage:** static checks 0 problems; scenario suite all green (44 today); battle tests all green (13);
   `DETERMINISM_OK`; `sanitize.sh` clean on the SDL3 build.
4. **Thresholds:** 2D and post pass exact (0 differing pixels) between backends on the same machine; 3D may differ at
   polygon edges (llvmpipe vs lavapipe, GL vs Metal); agree a per-scenario threshold, record it in the scenario, and
   look at every diff image above it. Structural differences (missing layer, wrong blend, flipped, wrong depth) are
   bugs.
5. **Do not use `SIM_DEBUG_SHOT_EVERY` for A/B** (vblank counter, not rendered frames).

#### Capture on SDL GPU (owned by 2c, needs 2b's composite)

The DS writes the captured image into VRAM during frame N; the game displays it from VRAM in frame N+1 at the
earliest (it reads VRAM, it never waits on the capture). Proposal: render the capture into a GPU texture in frame N,
download it with a transfer buffer, and write VRAM at the start of frame N+1 before the game thread runs, with a
fence wait only if the download is not finished. Lockstep stays deterministic because the VRAM write always lands at
the same point. Verify against the GL backend frame by frame on the motion-blur scenario; if any frame differs,
fall back to a synchronous wait on capture frames only (capture is rare).

## How to run the team (lessons from team 2)

- One Muse worker per workstream, each in its own devserver worktree; the integrator merges with `git am -3` and
  moves commits to the Mac with git bundles. Workers never push.
- Ramp up two workers at a time: ten started together all hit gateway 429s. Alternate models (`tbh-1005`,
  `tbh-1015`).
- New game `.c` files go in `platinum.us/main.lsf.in` (`src/meson.build` is generated); new simulator sources in
  `libraries/sim/src/meson.build`; regenerate `libntr.patch` after every libntr commit.
- Fixed-frame screenshots move whenever timing changes; anchor golden scenarios to engine events.
- Every simulator change that touches pointers: remember the Mac maps statics above 4 GB (the `OSi_ROUND` bug only
  crashed there). Run the suite on the Mac before pushing.

## Open risks

- **Metal is untested until the Mac runs it.** MSL generation and binding mapping are the likeliest silent failure;
  1c's self-test on the Mac retires most of it early.
- **Capture readback** on SDL GPU (latency vs determinism), see above.
- **Exact depth equality** for the stat-change effect on Vulkan and Metal.
- **std140 layouts** for the GPU 2D shader's many integer uniforms and arrays.
- **Pixel-exactness** of 3D between rasterisers; thresholds needed.
- **ImGui version**: the vendored ImGui may predate the SDL GPU backend (`imgui_impl_sdlgpu3`); 2c decides the
  smallest update.
- **The simulator patch is a fork in practice**: upstream libntr renderer fixes become manual merges.
